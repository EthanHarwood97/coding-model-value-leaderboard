Method

Click to expand

Coder. The mean of the two LiveBench scores: Agentic Coding and Coding. Every row has both, so it compares cleanly across the whole table, and Value is built on it.

Frontend. The mean of all three tracked scores, vision included, for work where reading screenshots and design references matters. Where a model has no vision result, Frontend averages the two LiveBench scores instead, so thin MMMU-Pro coverage does not push anyone out.

Agentic floor. An Agentic Coding score below 42 counts at 60% inside Coder and Frontend. Below that line the tasks fail often enough that the raw score overstates the model, and the discount stops a strong Coding score from carrying a mistake-prone agent to the top. The Agentic column always shows the raw LiveBench number; a dotted underline marks a value that is discounted.

Value. The Coder score divided by output price per million tokens, then scaled by 60% for models under the agentic floor. It answers the question that matters when you pay per token: how much usable coding score does one dollar buy? A model that fails agentic tasks often is not a bargain, however cheap it is. Higher is better, and free models have no price to divide by, so they show a dash.

Agentic Coding is the mean of LiveBench's python, javascript, and typescript tasks. Coding is the mean of code_generation and code_completion. The arithmetic matches livebench.ai exactly, computed from the same official CSVs.

Vision is MMMU-Pro, scored 0–100: image, chart, diagram, and document understanding. The primary number comes from Artificial Analysis, which runs the benchmark itself under one protocol and covers the newest models. Where a model has several AA reasoning-effort results, the table uses its best. Where AA has no result, we fall back to the published standard score (BenchLM.ai, then llm-stats.com). Hover any vision cell to see which one it is.

Vision estimates. A cell like 79.4+ est. means no MMMU-Pro result exists yet, so the model inherits the newest scored model in its own line as a floor. Read it as "no worse than 79.4". The comparison stays inside a line, never across lines or model sizes, and it assumes the newer model is at least as good. That usually holds, but not always, which is why estimates stay out of the Frontend score, the Coder score, and the rank.

Effort configs. LiveBench tests some models at several reasoning-effort settings, and each result gets its own row here. Claude Opus 5.5 appears at Max Effort and at xHigh Effort, for example. Same model, different settings.

Prices come from this repo's data/models.json when a model is tracked there, otherwise from LiveBench's own cost file for the same release. Output price per million tokens, USD.

Freshness. The table rebuilds from those source files on the same daily schedule as the full leaderboard.
